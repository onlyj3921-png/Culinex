KNOWN RISKS / LIMITATIONS
------------------------------------------------------------
1. Never compiled: syntax/type/API errors are likely somewhere (typical for ~3000 uncompiled lines). Run flutter analyze first.
2. Dependency versions in pubspec.yaml are caret ranges chosen offline; APIs (go_router, share_plus, file_picker, Riverpod) may differ in current releases. Theme classes were kept to ones stable across recent Flutter versions.
3. Free/Premium split and 'advanced reports' definition are my proposal; change in lib/core/features.dart. No Free-plan count limits were invented.
4. Estimated profit (sales - expenses) can mislead if ingredient purchases are logged late; labelled estimated, never net.
5. Weekly buckets use SQLite week-of-year (Monday first), not ISO weeks; labelled in the Reports screen.
6. Stock quantities are entered in base units (g/ml/pcs).
7. Calculator doubles match the spreadsheet; stored money is integer sen, so cost snapshots are stored as fractional sen.
8. Bahasa Melayu text is developer-written, not native-reviewed. Disclaimer text is not legal advice.
9. Local-only data: if the phone is lost without a backup, data is lost. Backup is manual.
10. Package name is a placeholder (com.culinex.culinex) and must be confirmed before any store listing.

------------------------------------------------------------
Confirmed defects found by reading the code, and fixed:
 1. calculator_screen.dart: changing the pack unit to another unit family left the hidden "used unit" in the old family, causing a "Unit mismatch" while the picker looked blank. Used unit now follows the pack unit family.
 2. calculator_screen.dart, stock_screen.dart: TextEditingControllers were disposed right after a dialog closed (exit animation can still use them: debug-mode crash risk). No longer disposed there.
 3. providers.dart: search providers (ingredients, recipes) kept one cached instance per typed string and re-ran all of them after every write. Now autoDispose.
 4. database.dart (backup): a plain file copy of an open database can be inconsistent. Backup now uses VACUUM INTO (single consistent file), with a copy fallback for old SQLite.
 5. database.dart (restore): stale -wal/-shm/-journal files could be applied to the restored file; a database that merely contained an app_meta table passed validation; a failed copy left no way back. Now: sidecar files deleted, all 7 CULINEX tables required, previous data copied back if the restore copy fails.

 7. sales_screen.dart, expenses_screen.dart, ingredients_screen.dart: on Android 15+ (edge-to-edge) the bottom sheet buttons / last editor button could sit under the system navigation bar. Added SafeArea / bottom padding.

SIMPLE-CALCULATOR FIX ADDENDUM (real-device QA finding from V7; Dart/Flutter still unavailable here, nothing compiled or run on a device)
------------------------------------------------------------
Bug: Simple tab at launch showed "CHECK: an ingredient row is incomplete" and "Fix inputs" with no visible row.
Root cause: Simple mode feeds the engine one hidden row built from the cost field; an empty/non-numeric field gives that row no price, which the engine correctly calls incomplete.
Fix (UI only): lib/core/simple_cost.dart (classifySimpleCost), guard in _resultsCard (empty -> neutral prompt, invalid -> red prompt, both with "—" in all 8 results), 2 new EN/MS strings. Engine, Advanced tab, database and formulas unchanged.
Tests run here: tools/test_simple_cost.py (41 checks: classifier cases, screen model incl. valid path vs V1.2 golden t1, strings, source assertions): 41/41. Against the pre-fix source the suite fails 7 checks (detects the bug).
Written but NOT run: test/simple_cost_test.dart (needs flutter test). No widget test was added.
