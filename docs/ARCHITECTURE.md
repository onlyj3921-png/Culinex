# CULINEX architecture and database

## Layers
* `packages/culinex_engine` — pure Dart (no Flutter): units, per-row cost, totals, suggested price, profit/margin, input status.
  Port of AutoFood Profit Calculator V1.2. Every number in the app's calculator and recipe screens comes from `calculate()`.
* `assets/db/schema.sql`, `assets/db/queries.sql` — single source for the SQLite schema and report SQL (loaded by the app, executed by `tools/test_sql.py`).
* `lib/data` — `AppDatabase` (open, backup, restore), `Repo` (all SQL), models.
* `lib/state/providers.dart` — Riverpod providers; `dataVersionProvider` is bumped after every write to refresh screens.
* `lib/ui` — screens. `lib/core` — theme (black/white/gold), RM formatting, EN/MS strings, plan gating.
* Navigation (go_router): tabs Home · Calculator · Recipes · Sales · More; full-screen: recipe/ingredient editors, ingredients, stock, expenses, reports, settings.

## Money and units
Money is stored as integer sen. Stock is stored in base units (g, ml, pcs). Units: g, kg, ml, L, pcs; weight/volume/pieces cannot mix.
Engine arithmetic uses doubles exactly like the spreadsheet (matched within 1e-9 relative on all golden vectors).

## Tables
ingredients(pack price/size/unit, track_stock, stock_base, low_stock_base) · ingredient_price_history · recipes(servings, target_margin, other_costs_sen, own_price_sen) ·
recipe_items(ingredient, qty, unit) · sales(recipe?, qty, unit_price_sen, **unit_cost_sen snapshot**, sold_on) · expenses(category, amount_sen, spent_on) ·
stock_movements(kind, signed qty_base, sale_id?) · app_meta(schema_version, lang). View `v_recipe_cost`.
Rules enforced by the database: size > 0, price ≥ 0, margin 0..<1, servings > 0, quantity > 0, expense > 0, valid unit/category/date, unit family must match the ingredient (trigger), movement sign by kind.
Triggers: price history; sale → automatic stock deduction for tracked ingredients (scaled by servings sold); voiding a sale restores stock; stock balance updates.
Soft deletes (`deleted_at`) everywhere; sales keep their cost snapshot so price changes never rewrite history; recipes always cost from CURRENT ingredient prices.

## Definitions shown in the UI
Estimated profit = sales − expenses (cash view). Estimated gross profit = revenue − recipe cost at time of sale (recipe-linked sales only). Neither is net profit; the disclaimer is shown beside profit figures.

## Free vs Premium (owner can change in `lib/core/features.dart`)
Free: calculator, recipes, ingredients, sales, expenses, daily/weekly/monthly totals and breakdown. Premium: stock tracking + movements + inventory value + low-stock banner, profit trend chart, stock reports.
There is NO billing. `planProvider` returns Free in release builds; a debug-only switch exists for testing. Local flags are not secure entitlement: real enforcement needs store purchase verification + server check.

## Offline / internet
Everything works offline. Nothing requires internet in this build (no accounts, no sync).

## Backup and recovery
Settings → Back up now: copies the SQLite file and opens the share sheet. Restore: validates (integrity_check, schema version), keeps `culinex.db.before_restore`, replaces the DB, app restarts.
Planned (not built): Supabase accounts + cloud sync with row-level security.

## Not implemented
Accounts/cloud, payments, push/system low-stock notifications (in-app banner only), CSV/PDF export, launcher icon/splash assets, Android project files (generated by `flutter create`).
